## Coordinator-approved identity-type amendment

On 2026-10-01 the coordinator approved one narrow correction to the frozen
REQ-EH1 interpretation. The independently pinned K2 `git:HEAD` row originates
from `git rev-parse HEAD`; it is a Git SHA-1 commit identity and must be exactly
40 hexadecimal digits. It is not a file SHA-256 even though the historical
receipt field is named `entrySha256`. Every file identity remains exactly 64
hexadecimal SHA-256 digits. Registry v3 records the source type at K2 roster
index 16 as `identityKinds["16"] = "git-sha1"`; v1/v2 compatibility recognizes
only the literal legacy pseudo-path `git:HEAD`. Focused and auxiliary controls
pair a valid 40-hex Git identity with invalid 64-hex Git and invalid 40-hex file
identities. This amendment changes no frozen requirement text above.
