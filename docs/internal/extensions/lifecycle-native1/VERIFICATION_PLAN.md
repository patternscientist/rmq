## Conditional and intentionally separate checks

- Run existing NativeImage regression clients when additive Cargo/lib/build glue changes their behavior. Old query success remains background for the new consumer.
- Additional native-platform validation is required only if claiming that platform; this assignment certifies Windows x64 MSVC with Lean 4.22 only. No POSIX support is inferred.
- Reuse predecessor lifecycle/native campaigns only for explicitly matched unchanged consumed-source hashes and applicable formal conclusions. Do not run historical whole-checkout pins against the private join or rewrite old evidence.
- The full campaign aggregate and fresh-blind exact-candidate audit belong to the coordinator. This worker does not run scripts/gate.ps1 merely to duplicate its required standalone final checks.
- If source/load-bearing checker changes, invalidate its transitive consumers. A report/ledger-only edit requires narrow claim/scope/design recertification and new input pins; it does not by itself invalidate execution against unchanged source.

## Concurrency, failure and stop discipline

Use Local\RMQLifecycleImplementationHeavy20260920 for expensive work. Only one heavy Lean/Lake/native runner may use a cache/build tree at a time. Record separate cache identity where applicable. Any multi-minute process must use the owned facility and preserve its failure/captures. After timeout inspect owned surviving children, CPU/artifact progress, direct prerequisites and accidental full-build fallback. Resume live owned work; do not start duplicates. Retry ended work only after a recorded material change and retain the failed attempt.

The dependency order is reviewed producers and scoped acceptance -> startup inventory/freeze -> actual Lean export/refinement -> C consumption -> positive ownership/failure/capacity observations -> conclusions -> source freeze -> complete replay -> completed report -> final report-sensitive checks -> committed-range checks/external delivery pins -> coordinator review/aggregate/blind audit/acceptance. Output-dependent decisions cannot gate their own evidence producer.

Valid terminal status requires the complete local target, an exact-target formal obstruction, a genuine evidenced external blocker, or explicit redirection. Difficulty, elapsed time, prototype success or a clean commit does not close a row. If a necessary edit lies outside scope, report the exact dependency and proposed minimal amendment before editing it.
