## Findings and implementation dispositions

1. Base integrity controls check decoded outer arrays inadequately: the generic helper removes empty lines and deletes redirect files. Disposition: use the protected production byte-copy child for actual runner capture. Preserve existing inner checks. A narrow invocation-local retention adapter copies the bottom launcher's raw redirect files at cleanup, then forwards deletion to the actual cmdlet. The global helper and process framework remain unchanged.
2. Base wrapper lacks a mandatory Kind check, allowing an omitted profile to execute an empty action. Disposition: explicit missing/empty rejection before launch. A subsequent review found that case-insensitive ValidateSet/dispatch and case-sensitive predicate disagreed on FULL. Disposition: normalize Kind once before dispatch; the supported canonical profiles stay six.
3. The current shared predicate initially still trusted normalized launcher arrays, permitting a blank-only launcher stream. Disposition: require retained raw launcher stdout/stderr to be exactly empty as well as the existing arrays. Scope-local Remove-Item interception captures only resolved invocation TempRoot redirect suffixes, forwards real cleanup even after copy failure, records retention failures and vanishes on return. The reviewer found this suitably narrow; it does not replace launch, ownership, termination or global commands.
4. The new harness registry initially froze only IDs/order, leaving kind/case/stream/outcome fields mutable. A concrete mutation could turn success-extra-stderr into a positive while retaining a reject label. Disposition: independently derive and check each operational field and actual predicate mapping from the fixed ID contract before execution. Metadata cannot select a weaker experiment.
5. The blank-launcher control initially caught the expected stream error before independently checking ordinary exit and the opposite stream. Blank output plus exit7 could conceal an unrelated failure. Disposition: before accepting rejection, require actual launcher0, no timeout/overflow/retention error, empty decoded arrays, exactly one platform newline in the target raw stream and exactly empty opposite raw stream. These are real launcher-process tests with a synthetic inner capture object; they are not native inner-stage runs.

Main harness fixture reach was source-reviewed: one injection is inserted in the generated runner stage body before production stage assertions; complete production prefix and catch/finally/verdict suffix are retained. Expected rejection runs the existing restoration finally. A restoration failure changes the caught diagnostic and cannot satisfy the expected exact stream failure.
