## Shared objects and predicates

`source` owns numeric registers `[1,0,2,0,0,0,0,0]`, memory `[some 0,some 11,some 22]`, empty key banks, PC 0 and running status. `original` is its abstract memory. The source interval `[1,3)` overlaps destination `[0,2)`. `finalizerCode = Finalizer.code 0`; `forward` executes that actual fourteen-instruction fragment for `Finalizer.cost 1 2 = 23` steps. Its final memory is `[some 11,some 22]`, its ordered attempted reads are `[(1,some 11),(2,some 22)]`, and exactly one numeric release occurs. `source_entry`, `source_initialized` and `forward_accept` prove the unchanged production predicates on these complete objects.

The predicate signatures used without weakening are:

* `Descriptor.OutputReceipt t`: exact action `move 0 3`, `after = execute (move 0 3) before`, and destination register 0 equals prior register 3.
* `Finalizer.Initialized memory 1 2`: for every `j < 2`, there exists a value with `memory (1+j) = some value`.
* `Finalizer.Entry 0 1 2 s`: running status, PC 0, extent 3, registers 0 = 1 and 2 = 2, initialization of both source words, and absence outside the declared extent.
* `Finalizer.FinalOutput original 1 2 s`: extent exactly 2, every destination `j < 2` equals `original (1+j)`, and absence at every address at or above the extent.
* `copiedAt r memory i loadIndex storeIndex`: there exist actual `ArrayTransition` occurrences at the two supplied indices whose projections satisfy the unchanged `Finalizer.CopyReceipt memory 1 i`. That receipt identifies `load 5 0` and `store 1 5`, source and destination register values, the actual source reply, the loaded register, the immediate load-to-store state equality, the destination cell, and the ordered read/write observations.
* `Retired s`: `s.keyExtent = 0 ∧ s.keyRegExtent = 0`. This is the exact bank-extent projection, not a complete readiness predicate. No claim that pointwise default contents imply zero extent is used.
* `∀ i ∈ program, i.Fits 8`: the production `Instruction.Fits` predicate quantifies every word in every instruction's encoding, including instructions that are never executed. Width 8 deliberately gives a representable overflow example within the language's intrinsic 32-bit operand type; this is not a counterexample to the canonical program's proved width bound.

## Proof digestion

These controls separate failures that a correct output prefix alone would miss: a wrong source register, an uninitialized actual load, an extra owned suffix, absent releases, retained key resources, or an uncleared register at the real second-query entry. Overlap order matters because the backward version overwrites the next source word before reading it. The tenth control now runs on the same produced owner as the real service and rejects through a checked projection of its entry contract. The representative native tests exercise the new finite interpreter, including genuine scalar finalization and key retirement. Their live limits are finite fixtures, represented word inputs/endpoints, logical array sizes, and an entry-ABI rejection rather than a claimed wrong numerical answer. They do not identify native backing capacity or external aliases. The next skeptical question is whether the public capstone derives the same guards for every input and depends on these operational conclusions; that remains the role of the generic proofs and independent expected-type/dependency consumer, not finite tests.
